Zec Agent Wallet playground TESTNET

Real shielded transactions on Zcash testnet, with test coins. No language model runs here: you press the buttons an agent would call, and you see the exact JSON the model would receive. Two wallets run side by side: a designer who bills, and a customer whose agent pays.

Try this: 1) the designer's agent issues a bill; 2) the customer's agent tries to pay it and is refused; 3) open the owner window, approve the bill with the password from the submission; 4) the agent pays it, and paying again returns the same payment; 5) the designer's agent checks its bill. Then send the forged bill and see what the model gets.

Designer's agent

Issues a 0.001 TAZ bill to the customer through request_payment. The payment link goes to the customer's wallet, not to the model.

-

Attacker

Sends the customer a forged bill: ten times the amount, an unknown address and a prompt injection in the memo.

Customer's owner

Approvals happen only here, behind the wallet password. The owner sees the sender's text and the address; the model never does.
